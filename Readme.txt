🔹 𝟭. 𝗘𝗻𝗰𝗮𝗽𝘀𝘂𝗹𝗮𝘁𝗶𝗼𝗻
 𝗗𝗲𝗳: Binding 𝗱𝗮𝘁𝗮 + 𝗺𝗲𝘁𝗵𝗼𝗱𝘀 in one unit, restricting direct access.
 𝗜𝗻 𝗝𝗮𝘃𝗮: 𝗽𝗿𝗶𝘃𝗮𝘁𝗲 fields + 𝗴𝗲𝘁𝘁𝗲𝗿𝘀/𝘀𝗲𝘁𝘁𝗲𝗿𝘀.
✅ 𝗪𝗵𝗮𝘁 𝘁𝗼 𝘀𝗮𝘆 𝗶𝗻 𝗶𝗻𝘁𝗲𝗿𝘃𝗶𝗲𝘄:
 “𝗘𝗻𝗰𝗮𝗽𝘀𝘂𝗹𝗮𝘁𝗶𝗼𝗻 gives me 𝗱𝗮𝘁𝗮 𝗵𝗶𝗱𝗶𝗻𝗴 and 𝗰𝗼𝗻𝘁𝗿𝗼𝗹𝗹𝗲𝗱 𝗮𝗰𝗰𝗲𝘀𝘀. It makes classes 𝗹𝗼𝗼𝘀𝗲𝗹𝘆 𝗰𝗼𝘂𝗽𝗹𝗲𝗱 and 𝗺𝗮𝗶𝗻𝘁𝗮𝗶𝗻𝗮𝗯𝗹𝗲.”

🔹 𝟮. 𝗔𝗯𝘀𝘁𝗿𝗮𝗰𝘁𝗶𝗼𝗻
 𝗗𝗲𝗳: Exposing only the 𝗿𝗲𝗾𝘂𝗶𝗿𝗲𝗱 𝗳𝘂𝗻𝗰𝘁𝗶𝗼𝗻𝗮𝗹𝗶𝘁𝘆, hiding internal details.
 𝗜𝗻 𝗝𝗮𝘃𝗮: 𝗮𝗯𝘀𝘁𝗿𝗮𝗰𝘁 𝗰𝗹𝗮𝘀𝘀𝗲𝘀, 𝗶𝗻𝘁𝗲𝗿𝗳𝗮𝗰𝗲𝘀.
✅ 𝗪𝗵𝗮𝘁 𝘁𝗼 𝘀𝗮𝘆 𝗶𝗻 𝗶𝗻𝘁𝗲𝗿𝘃𝗶𝗲𝘄:
 “𝗔𝗯𝘀𝘁𝗿𝗮𝗰𝘁𝗶𝗼𝗻 𝗿𝗲𝗱𝘂𝗰𝗲𝘀 𝗰𝗼𝗺𝗽𝗹𝗲𝘅𝗶𝘁𝘆 and makes the system 𝗳𝗹𝗲𝘅𝗶𝗯𝗹𝗲. I work with 𝗰𝗼𝗻𝘁𝗿𝗮𝗰𝘁𝘀 𝗿𝗮𝘁𝗵𝗲𝗿 𝘁𝗵𝗮𝗻 𝗶𝗺𝗽𝗹𝗲𝗺𝗲𝗻𝘁𝗮𝘁𝗶𝗼𝗻𝘀.”

🔹 𝟯. 𝗜𝗻𝗵𝗲𝗿𝗶𝘁𝗮𝗻𝗰𝗲
 𝗗𝗲𝗳: Mechanism to 𝗿𝗲𝘂𝘀𝗲 𝗲𝘅𝗶𝘀𝘁𝗶𝗻𝗴 𝗰𝗼𝗱𝗲 by creating 𝗜𝗦-𝗔 relationships.
 𝗜𝗻 𝗝𝗮𝘃𝗮: 𝗲𝘅𝘁𝗲𝗻𝗱𝘀, 𝘀𝘂𝗽𝗲𝗿.
✅ 𝗪𝗵𝗮𝘁 𝘁𝗼 𝘀𝗮𝘆 𝗶𝗻 𝗶𝗻𝘁𝗲𝗿𝘃𝗶𝗲𝘄:
 “𝗜𝗻𝗵𝗲𝗿𝗶𝘁𝗮𝗻𝗰𝗲 gives me 𝗰𝗼𝗱𝗲 𝗿𝗲𝘂𝘀𝗲 and enables 𝗿𝘂𝗻𝘁𝗶𝗺𝗲 𝗽𝗼𝗹𝘆𝗺𝗼𝗿𝗽𝗵𝗶𝘀𝗺 via overriding. But I must use it carefully, since it creates 𝘁𝗶𝗴𝗵𝘁 𝗰𝗼𝘂𝗽𝗹𝗶𝗻𝗴.”

🔹 𝟰. 𝗣𝗼𝗹𝘆𝗺𝗼𝗿𝗽𝗵𝗶𝘀𝗺
 𝗗𝗲𝗳: 𝗢𝗻𝗲 𝗶𝗻𝘁𝗲𝗿𝗳𝗮𝗰𝗲, 𝗺𝗮𝗻𝘆 𝗶𝗺𝗽𝗹𝗲𝗺𝗲𝗻𝘁𝗮𝘁𝗶𝗼𝗻𝘀.
 𝗜𝗻 𝗝𝗮𝘃𝗮:
𝗖𝗼𝗺𝗽𝗶𝗹𝗲-𝘁𝗶𝗺𝗲: 𝗠𝗲𝘁𝗵𝗼𝗱 𝗼𝘃𝗲𝗿𝗹𝗼𝗮𝗱𝗶𝗻𝗴
𝗥𝘂𝗻𝘁𝗶𝗺𝗲: 𝗠𝗲𝘁𝗵𝗼𝗱 𝗼𝘃𝗲𝗿𝗿𝗶𝗱𝗶𝗻𝗴
✅ 𝗪𝗵𝗮𝘁 𝘁𝗼 𝘀𝗮𝘆 𝗶𝗻 𝗶𝗻𝘁𝗲𝗿𝘃𝗶𝗲𝘄:
 “𝗣𝗼𝗹𝘆𝗺𝗼𝗿𝗽𝗵𝗶𝘀𝗺 gives me 𝗲𝘅𝘁𝗲𝗻𝘀𝗶𝗯𝗶𝗹𝗶𝘁𝘆 and 𝗳𝗹𝗲𝘅𝗶𝗯𝗶𝗹𝗶𝘁𝘆. I can introduce 𝗻𝗲𝘄 𝗯𝗲𝗵𝗮𝘃𝗶𝗼𝗿𝘀 without modifying existing code (𝗢𝗖𝗣).”

⚖️ 𝗛𝗼𝘄 𝗧𝗵𝗲𝘆 𝗖𝗼𝗻𝗻𝗲𝗰𝘁 𝘁𝗼 𝗣𝗿𝗶𝗻𝗰𝗶𝗽𝗹𝗲𝘀
✅𝗘𝗻𝗰𝗮𝗽𝘀𝘂𝗹𝗮𝘁𝗶𝗼𝗻 → leads to 𝗶𝗻𝗳𝗼𝗿𝗺𝗮𝘁𝗶𝗼𝗻 𝗵𝗶𝗱𝗶𝗻𝗴 (helps in 𝗹𝗼𝗼𝘀𝗲 𝗰𝗼𝘂𝗽𝗹𝗶𝗻𝗴, 𝗦𝗥𝗣).
✅𝗔𝗯𝘀𝘁𝗿𝗮𝗰𝘁𝗶𝗼𝗻 → drives 𝗰𝗼𝗻𝘁𝗿𝗮𝗰𝘁-𝗳𝗶𝗿𝘀𝘁 𝗱𝗲𝘀𝗶𝗴𝗻 (𝗜𝗦𝗣, 𝗗𝗜𝗣).
✅𝗜𝗻𝗵𝗲𝗿𝗶𝘁𝗮𝗻𝗰𝗲 → gives 𝗿𝗲𝘂𝘀𝗮𝗯𝗶𝗹𝗶𝘁𝘆 + 𝗽𝗼𝗹𝘆𝗺𝗼𝗿𝗽𝗵𝗶𝘀𝗺 (but apply carefully, 𝗽𝗿𝗲𝗳𝗲𝗿 𝗰𝗼𝗺𝗽𝗼𝘀𝗶𝘁𝗶𝗼𝗻).
✅𝗣𝗼𝗹𝘆𝗺𝗼𝗿𝗽𝗵𝗶𝘀𝗺 → enables 𝗢𝗖𝗣 and 𝗳𝗹𝗲𝘅𝗶𝗯𝗶𝗹𝗶𝘁𝘆 in system design.

🔥 𝗚𝗼𝘁𝗰𝗵𝗮𝘀 (𝗜𝗻𝘁𝗲𝗿𝘃𝗶𝗲𝘄 𝗧𝗿𝗮𝗽𝘀)
🙄 𝗳𝗶𝗻𝗮𝗹 methods/classes → block inheritance/overriding.
🤔 𝘀𝘁𝗮𝘁𝗶𝗰 methods → no runtime polymorphism, resolved at compile time.
🙄𝗽𝗿𝗶𝘃𝗮𝘁𝗲 methods → not inherited, not overridden.
🤔𝗖𝗼𝗻𝘀𝘁𝗿𝘂𝗰𝘁𝗼𝗿𝘀 → cannot be 𝗮𝗯𝘀𝘁𝗿𝗮𝗰𝘁, 𝗳𝗶𝗻𝗮𝗹, 𝘀𝘁𝗮𝘁𝗶𝗰.
🤔𝗠𝘂𝗹𝘁𝗶𝗽𝗹𝗲 𝗶𝗻𝗵𝗲𝗿𝗶𝘁𝗮𝗻𝗰𝗲 𝗼𝗳 𝗰𝗹𝗮𝘀𝘀𝗲𝘀 → not allowed, solved via 𝗶𝗻𝘁𝗲𝗿𝗳𝗮𝗰𝗲𝘀.
